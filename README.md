# 1C Syntax MCP Server

MCP-сервер, который отдаёт LLM полнотекстовый поиск и точные ответы по официальной
справке платформы 1С:Предприятие — встроенному языку (BSL) и языку запросов (SDBL),
взятым из реально установленной копии платформы, а не из памяти модели.

Публикация на Инфостарт:
https://infostart.ru/1c/articles/2657968/

![Инфостарт](https://infostart.ru/bitrix/templates/sandbox_empty/assets/tpl/abo/img/logo.svg)

## Зачем это нужно

Языковые модели путают сигнатуры функций 1С, придумывают несуществующие параметры
и не различают одноимённые методы разных объектов. Этот сервер строит индекс прямо
из `.hbk`-файлов установленной платформы (`shcntx_ru.hbk` и др.) и отвечает по нему,
а не по обучающим данным — поэтому ответы соответствуют именно той версии платформы,
что стоит у вас, включая самые новые релизы.

Возможности:
- Полнотекстовый поиск функций, методов, свойств и объектов на русском и английском —
  по имени, фразе на естественном языке или описанию. Шесть уровней ранжирования:
  точное совпадение → алиасы намерений → раскладка клавиатуры/гомоглифы → опечатки
  (fuzzy) → полнотекстовый bm25. Устойчив к ЙЦУКЕН↔QWERTY и опечаткам.
- Детальная информация о функции, включая структурные параметры (имя, тип,
  обязательность, описание); при коллизии имени у разных объектов — список
  кандидатов вместо случайного выбора.
- Точная адресация `Объект.Метод` (`get_by_fqn`) без коллизий одноимённых членов.
- Автодополнение по частичному имени.
- Проверка вызова функции: существование имени и, где выводимо из кода, арность —
  честно возвращает «не могу определить», а не гадает.
- Встроенный язык (BSL) и язык запросов (SDBL) — раздельно через параметр `language`.
- Несколько установленных версий платформы одновременно, включая сравнение (`diff`)
  между версиями.
- Два транспорта: локальный stdio (venv) и HTTP-контейнер с веб-панелью для загрузки
  справки без установленной 1С на той же машине.

Измеренное качество поиска: recall@5 = 0.881, MRR = 0.785 на наборе из 42 контрольных
запросов (`tests/`). Обоснование архитектуры, альтернативы хранения и история замеров —
[docs/IMPROVEMENT_PLAN.md](docs/IMPROVEMENT_PLAN.md).

## Как это устроено

`.hbk` — не архив 7z (хотя выглядит похоже), а контейнер формата 1Cv8; читается
напрямую стандартной библиотекой Python (`hbk_reader.py`), без внешних утилит.
Дальше: структурный разбор HTML (`html_parser.py`, через `lxml`) → сегментация
идентификаторов и глоссарий сокращений (`segmentation.py`) → нормализация (регистр,
`ё`, гомоглифы, раскладка — `normalization.py`) → построение SQLite-индекса с FTS5
(`syntax_db.py`). Поиск идёт по строгим уровням: более раннее совпадение никогда не
перебивается более поздним, чем задаётся приоритет разных сигналов без нужды в весах.

## Установка

Два независимых способа. Docker — контейнер, MCP по HTTP, веб-панель для загрузки
`.hbk` без установленной 1С на той же машине. venv — локальный Python, MCP по
stdio, без сети.

| | Docker | venv |
|---|---|---|
| Нужен Python на машине | нет | да |
| 1С установлена на этой же машине | необязательно (bind-mount или загрузка через панель) | обязательно |
| Транспорт | HTTP (`streamable`) | stdio |
| Несколько клиентов одновременно | да | нет |

### Вариант 1. Docker (рекомендуется)

Нужен Docker Desktop (или Docker Engine + Compose) и ~300-400 МБ свободного места
(образ ~270 МБ + 52-60 МБ на каждую собранную версию индекса).

#### 1С уже установлена на этой машине

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
# поправьте путь установки внутри файла, если он отличается от C:\Program Files\1cv8
docker compose up -d
docker compose logs -f syntax-mcp   # ждите строку "Uvicorn running on http://0.0.0.0:8765"
```

Раскладка `<версия>/bin/<файл>.hbk` одинакова на Windows и Linux, поэтому версии
обнаружатся автоматически — ничего загружать не нужно. Индекс для новейшей версии
соберётся сам в фоне (~10-20 секунд); откройте `http://127.0.0.1:8765/`, чтобы
увидеть список всех обнаруженных версий и статус сборки.

#### 1С на этой машине нет

```bash
docker compose up -d
```

Не создавайте `docker-compose.override.yml` — тогда контейнер поднимется без
bind-mount и будет ждать загрузки через панель. Откройте `http://127.0.0.1:8765/`,
введите версию платформы (например `8.5.1.1150` — она не хранится внутри `.hbk`,
поэтому вводится вручную) и загрузите `shcntx_ru.hbk` с машины, где 1С установлена:
`C:\Program Files\1cv8\<версия>\bin\shcntx_ru.hbk`. Дополнительно можно загрузить
`shquery_ru.hbk` (язык запросов) и `shlang_ru.hbk` (операторы BSL) — без них поиск
по объектам и методам всё равно работает. Сборка индекса запустится автоматически
после загрузки, займёт около 10-20 секунд.

Тот же результат без браузера — через API (это делает [INSTALL-AGENT.md](INSTALL-AGENT.md)):
```bash
curl -X PUT --data-binary @shcntx_ru.hbk http://127.0.0.1:8765/api/uploads/8.5.1.1150/shcntx_ru
curl -X POST -H "Content-Type: application/json" -d '{}' http://127.0.0.1:8765/api/versions/8.5.1.1150/build
curl http://127.0.0.1:8765/api/jobs/<job_id>   # опрашивать до "status":"done"
```

**Файлы `.hbk` — проприетарная документация 1С**: загружайте их только для
собственного использования, не публикуйте и не распространяйте.

### Вариант 2. Локальная установка (venv)

#### 1. Создать виртуальное окружение

```bash
git clone https://github.com/Romanlvanov/1c-syntax-mcp.git
cd 1c-syntax-mcp
python -m venv venv
venv\Scripts\activate  # Windows
# или
source venv/bin/activate  # Linux/Mac
```

#### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

Внешние утилиты (7z и т.п.) не требуются — `.hbk` читается через стандартную
библиотеку Python.

#### 3. Проверить, что сервер стартует

```bash
python server.py --build-index   # соберёт индекс новейшей версии со справкой, ~10-20 секунд
```

На реальных данных сборка занимает 10-20 секунд. Индекс каждой версии хранится
отдельным файлом `index/<версия>/syntax_index.sqlite` и переиспользуется, если
исходный `.hbk` не менялся (сверка по размеру/времени изменения, при расхождении —
по SHA-256). Собрать другую версию или все сразу:

```bash
python server.py --build-index --platform=8.3.19.1264  # конкретная версия
python server.py --build-index --all                    # все версии со справкой
python server.py --build-index --force                  # пересобрать, даже если актуален
```

При запуске без `--build-index` сервер сам найдёт новейшую версию со справкой и
соберёт для неё индекс, если он ещё не собран (если новейшая версия — тонкий
клиент без справки, будет использована более старая, у которой она есть).

## Подключение клиента

### Claude Code

Docker (HTTP-транспорт):
```bash
claude mcp add --transport http --scope user 1c-syntax http://127.0.0.1:8765/mcp
```

venv (stdio-транспорт):
```bash
claude mcp add --scope user 1c-syntax -- /путь/к/venv/bin/python /путь/к/1c-syntax-mcp/server.py
```
На Windows путь к интерпретатору — `venv\Scripts\python.exe`.

`--scope user` делает сервер доступным во всех проектах; `--scope project` —
только текущему (записывается в `.mcp.json`, можно коммитить).

### opencode

Добавьте в `%APPDATA%\opencode\opencode.jsonc` (Windows) или
`~/.config/opencode/opencode.jsonc` (Linux/Mac):

**Docker (HTTP):**
```jsonc
{
  "mcp": {
    "1c-syntax": {
      "type": "remote",
      "url": "http://127.0.0.1:8765/mcp",
      "enabled": true
    }
  }
}
```

**venv (stdio), Windows:**
```json
{
  "mcp": {
    "1c-syntax": {
      "type": "local",
      "command": ["C:\\путь\\к\\1c-syntax-mcp\\venv\\Scripts\\python.exe", "C:\\путь\\к\\1c-syntax-mcp\\server.py"],
      "enabled": true
    }
  }
}
```

**venv (stdio), Linux/Mac:**
```json
{
  "mcp": {
    "1c-syntax": {
      "type": "local",
      "command": ["~/1c-syntax-mcp/venv/bin/python", "~/1c-syntax-mcp/server.py"],
      "enabled": true
    }
  }
}
```

Проверить подключение: `claude mcp list` или `opencode mcp list` — сервер `1c-syntax`
должен быть в списке. Используйте `127.0.0.1`, а не `localhost` (на Windows он может
резолвиться и в `::1`); Docker-контейнер должен быть запущен раньше клиента — в
отличие от stdio, HTTP-транспорт клиент сам не поднимает.

## Инструменты

Панель поиска для самопроверки без MCP-клиента — `POST /api/search` (см. раздел
«Веб-панель»). Все инструменты, кроме `list_versions` и `diff_versions`, принимают
необязательный параметр `platform` — версия платформы; по умолчанию используется
новейшая версия с уже собранным индексом. Если индекс не собран, ответ инструмента
объясняет, как его собрать (CLI или панель), вместо непонятной ошибки.

### search_syntax

Поиск функций, методов, свойств и объектов 1С по имени, фразе на естественном
языке или описанию.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `query` | string | да | Запрос: имя или фраза на естественном языке |
| `limit` | number | нет | Максимум результатов (по умолчанию 10) |
| `kind` | string | нет | `object`\|`method`\|`property`\|`event`\|`ctor`\|`sdbl`\|`bsl_syntax` |
| `owner` | string | нет | Сузить до конкретного объекта-владельца |
| `language` | string | нет | `bsl`\|`sdbl`; по умолчанию ищет в обоих |
| `platform` | string | нет | Версия платформы |

```json
{"query": "как обрезать пробелы в строке", "limit": 5}
```

Каждый результат помечен полем `tier` — каким уровнем ранжирования он найден:
`exact` (точное совпадение имени/FQN) → `alias` (сработал алиас намерения,
например «пустое» → `ЗначениеЗаполнено`) → `layout` (раскладка ЙЦУКЕН↔QWERTY) →
`homoglyph` (гомоглиф-скелет, кириллица/латиница похожего написания) → `fuzzy`
(опечатка, rapidfuzz) → `bm25` (полнотекстовый поиск по описанию). Уровни строгие:
более раннее совпадение никогда не перебивается более поздним.

### get_function_info

Детальная информация о функции, методе или свойстве, включая структурные параметры
(имя, тип, обязательность, описание). Если имя неоднозначно (несколько
объектов-владельцев имеют член с таким именем), возвращает список кандидатов вместо
случайного выбора — уточните `owner` или используйте `get_by_fqn`.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `name` | string | да | Точное имя (русский или английский) |
| `owner` | string | нет | Объект-владелец, если имя неоднозначно |
| `language` | string | нет | `bsl` (по умолчанию) \| `sdbl` |
| `platform` | string | нет | Версия платформы |

```json
{"name": "СокрЛП"}
```

### get_by_fqn

Детальная информация по полному имени вида `Объект.Метод` — однозначная адресация
без коллизий имён.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `fqn` | string | да | Например: `Глобальный контекст.СтрДлина` |
| `language` | string | нет | `bsl` (по умолчанию) \| `sdbl` |
| `platform` | string | нет | Версия платформы |

```json
{"fqn": "Глобальный контекст.ЗаписатьJSON"}
```

### suggest_completion

Автодополнение по частичному имени функции.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `prefix` | string | да | Начало имени (например: `Стр`, `Str`) |
| `limit` | number | нет | Максимум предложений (по умолчанию 10) |
| `platform` | string | нет | Версия платформы |

```json
{"prefix": "Стр", "limit": 10}
```

### validate_syntax

Проверить вызов функции: существование имени и, где это выводимо из переданного
кода, арность вызова (по структурным параметрам справки). Поддерживает разрешение
вызовов через точку (`Получатель.Метод`), если тип получателя присвоен в этом же
коде через `Х = Новый Тип(...)`. **Честно не проверяет** реальный вывод типов, поток
управления и объекты метаданных конфигурации — в этих случаях возвращает
неопределённый результат вместо угадывания.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `code` | string | да | Код для проверки |
| `language` | string | нет | `bsl` (по умолчанию) \| `sdbl` |
| `platform` | string | нет | Версия платформы |

```json
{"code": "СтрДлина(\"текст\")"}
{"code": "Х = Новый Массив; Х.Добавить(1)"}
```

Ответ маркируется одним из трёх символов:
- **✓** (`ok: true`) — имя существует, и число аргументов укладывается в сигнатуру.
- **❌** (`ok: false`) — доказано неверно: имя не найдено, метод отсутствует у
  известного типа, арность вне диапазона, либо код не распознан.
- **⚠** (`ok: null`) — неразрешимо по переданному коду: нет структурных параметров
  в справке, неизвестен тип получателя, или имя неоднозначно между владельцами.

### list_versions

Список установленных версий платформы: у каких есть справка, какие уже
проиндексированы, сколько элементов в индексе каждой, откуда версия обнаружена
(установка на диске или загрузка через панель). Без параметров.

### diff_versions

Сравнить две версии платформы: что добавлено/удалено/изменено в справке BSL между
ними (сравнение по SDBL не проводится). Обе версии должны быть предварительно
собраны (`python server.py --build-index --platform=<версия>` или через панель).

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `from_version` | string | да | Например `8.3.19.1264` |
| `to_version` | string | да | Например `8.5.1.1150` |

## Веб-панель

Доступна только в Docker-режиме, по адресу `http://127.0.0.1:8765/` (офлайн,
без внешних ресурсов, на русском). Показывает список всех обнаруженных версий
платформы со статусом индексации, позволяет загрузить `.hbk` с индикатором
прогресса, запустить/пересобрать индекс с живым статусом сборки, сменить версию
по умолчанию, удалить версию и проверить поиск без подключения MCP-клиента.
В шапке — готовые команда и JSON-снипет для подключения клиента.

Роуты, которыми панель пользуется (пригодятся для автоматизации или отладки):

| Метод | Путь | Токен | Назначение |
|---|---|---|---|
| GET | `/api/health` | нет | `{"ok", "ready", "default_version", "fts5"}` |
| GET | `/api/state` | нет | Все версии, активные задачи сборки, адрес MCP |
| PUT | `/api/uploads/{version}/{kind}` | да | Загрузка `.hbk` сырым телом; `kind` ∈ `shcntx_ru`\|`shquery_ru`\|`shlang_ru` |
| POST | `/api/versions/{version}/build` | да | Запустить сборку → `{"job_id"}`; тело `{"force": bool}` |
| GET | `/api/jobs/{job_id}` | нет | Статус фоновой задачи |
| POST | `/api/default` | да | Сменить версию по умолчанию, тело `{"version"}` |
| DELETE | `/api/versions/{version}?with_files=1` | да | Удалить индекс (и файлы `.hbk`, если загружены через панель) |
| POST | `/api/search` | нет | Проба поиска, тело `{"query", "limit", "platform"}` |
| ANY | `/mcp` | — | MCP streamable HTTP |

«Токен: да» означает, что запрос требует заголовок `X-Panel-Token`, если задана
переменная `SYNTAX_MCP_PANEL_TOKEN` (по умолчанию она пуста, и проверки нет).
Версия — строка вида `8.5.1.1150`, проверяется на сервере регулярным выражением
`^\d+(\.\d+){1,3}$`.

## Навык 1cskills

В репозитории включён навык **1cskills** (`skills/1cskills/SKILL.md`) — большой
набор правил для AI-ассистентов при работе с кодом на языке 1С: BSL, язык
запросов, структура конфигурации. Ключевое: навык **обязывает** ассистента
проверять любые сведения о встроенных функциях через инструменты этого MCP-сервера,
а не полагаться на память модели.

Навык описывает:
- Обязательный алгоритм проверки синтаксиса через MCP, включая разрешение
  коллизий имён через `get_by_fqn`
- Контекст выполнения и директивы (`&НаКлиенте`, `&НаСервере` и т.д.)
- Структуру областей (Regions) для модулей объектов, менеджеров, форм и общих модулей
- Структуру файлов проекта (XML-дамп конфигурации) и структуру управляемых форм
- Библиотеку стандартных подсистем (БСП) и типовые паттерны
- Именование переменных, документирование кода, пометки изменений
- Язык запросов 1С (ВЫБРАТЬ, соединения, агрегатные функции, временные таблицы,

## Настройка

Применимо к Docker-режиму (HTTP); часть переменных действует и при локальном
запуске с `--transport http`. CLI-флаги имеют приоритет над переменными окружения.

### Переменные окружения

| Переменная | По умолчанию | В образе Docker | Назначение |
|---|---|---|---|
| `SYNTAX_MCP_TRANSPORT` | `stdio` | `http` | `stdio` \| `http` |
| `SYNTAX_MCP_HOST` | `127.0.0.1` | `0.0.0.0` | Адрес прослушивания HTTP |
| `SYNTAX_MCP_PORT` | `8765` | `8765` | Порт HTTP |
| `SYNTAX_MCP_INDEX_DIR` | `<репозиторий>/index` | `/data/index` | Каталог собранных индексов |
| `SYNTAX_MCP_UPLOAD_DIR` | `<репозиторий>/uploads` | `/data/hbk` | Куда панель кладёт загруженные `.hbk` |
| `SYNTAX_MCP_PLATFORM_PATHS` | пусто | — | Доп. каталоги установок 1С через запятую |
| `SYNTAX_MCP_DEFAULT_VERSION` | пусто | — | Принудительно закрепить версию по умолчанию |
| `SYNTAX_MCP_AUTO_BUILD` | `1` (включено) | — | Собирать индекс версии по умолчанию автоматически при старте |
| `SYNTAX_MCP_ALLOWED_HOSTS` | пусто | — | Список хостов через запятую для защиты `/mcp` от DNS-rebinding (например `127.0.0.1:*,localhost:*`); пусто — защита выключена |
| `SYNTAX_MCP_ALLOWED_ORIGINS` | пусто | — | То же для заголовка `Origin`; учитывается только вместе с `ALLOWED_HOSTS` |
| `SYNTAX_MCP_PANEL_TOKEN` | пусто | — | Если задан, изменяющие запросы к панели требуют заголовок `X-Panel-Token` |
| `SYNTAX_MCP_HTTP_STATELESS` | `1` (включено) | — | Режим `stateless` у MCP-сессии (между вызовами хранится только состояние индексов) |
| `SYNTAX_MCP_HTTP_JSON_RESPONSE` | `0` (выключено) | — | Отвечать обычным JSON вместо потока SSE |
| `SYNTAX_MCP_MAX_UPLOAD_MB` | `64` | — | Лимит размера файла при загрузке через панель |
| `SYNTAX_MCP_DB_THREADS` | `8` | — | Сколько потоков одновременно может обращаться к SQLite |
| `SYNTAX_MCP_PANEL_ENABLED` | `1` (включено) | — | `0` оставляет только `/api/health` и `/mcp`, без панели |
| `SYNTAX_MCP_LOG_LEVEL` | `info` | — | Уровень логирования (`debug`, `info`, `warning`, ...) |

Булево значение ложно, если после приведения к нижнему регистру равно `""`, `"0"`,
`"false"`, `"no"` или `"off"`; всё остальное — истина. Переменные для локальной
разработки — в [.env.example](.env.example) (скопируйте в `.env` рядом с
`docker-compose.yml`, Compose подхватит его сам).

### CLI-флаги (`python server.py ...`)

| Флаг | Назначение |
|---|---|
| `--transport {stdio,http}` | Перекрывает `SYNTAX_MCP_TRANSPORT` |
| `--host HOST` | Перекрывает `SYNTAX_MCP_HOST` |
| `--port PORT` | Перекрывает `SYNTAX_MCP_PORT` |
| `--index-dir PATH` | Перекрывает `SYNTAX_MCP_INDEX_DIR` |
| `--upload-dir PATH` | Перекрывает `SYNTAX_MCP_UPLOAD_DIR` |
| `--no-auto-build` | Выключает автосборку (одностороннее: включить поверх `SYNTAX_MCP_AUTO_BUILD=0` этим флагом нельзя) |
| `--build-index` | Режим сборки индекса вместо запуска сервера |
| `--platform VERSION` | С `--build-index`: собрать только эту версию |
| `--all` | С `--build-index`: собрать все версии со справкой (имеет приоритет над `--platform`) |
| `--force` | С `--build-index`: пересобрать, даже если индекс уже актуален |

## Обслуживание (Docker)

Тома: `syntaxmcp-index` (собранные индексы, 52-60 МБ на версию — можно удалить и
пересобрать без потерь за 10-20 секунд) и `syntaxmcp-hbk` (загруженные через
панель `.hbk` — удалять осторожно, если это единственный источник).
**Не запускайте `docker compose down -v`**, если хотите сохранить загруженные файлы.

```bash
docker compose logs -f syntax-mcp              # логи
docker compose restart                          # применить SYNTAX_MCP_* после правки .env
docker compose exec syntax-mcp python server.py --build-index --platform=8.5.1.1150 --force
docker compose restart syntax-mcp               # ОБЯЗАТЕЛЕН после сборки из CLI при работающем контейнере
docker compose build --no-cache && docker compose up -d   # обновление образа, тома сохраняются
```

Пересборку из панели (кнопка «Пересобрать») перезапускать не нужно — панель сама
переоткрывает индекс после успешной сборки. Образ собирается локально
(`image: 1c-syntax-mcp:local`), внешнего реестра нет — обновление означает
`git pull` + пересборку образа, а не `docker compose pull`.

## Диагностика

| Симптом | Причина | Проверка |
|---|---|---|
| `unhealthy` в `docker compose ps` в первые ~90 с | автосборка индекса ещё идёт | `docker compose logs`, дождаться `start_period` |
| Поиск ничего не находит, `fts5: false` в `/api/health` | sqlite3 в образе без FTS5 (не должно происходить — проверяется при сборке образа) | пересобрать образ: `docker compose build --no-cache` |
| `PermissionError` при сборке индекса | том создан не тем пользователем | `docker compose down -v && docker compose up -d` — новый том унаследует владельца из образа |
| Клиент получает connection refused (Docker) | `SYNTAX_MCP_HOST` переопределён с `0.0.0.0` на что-то другое | не переопределяйте `SYNTAX_MCP_HOST` без причины |
| Сервер не запускается (venv) | окружение не активировано или зависимости не установлены | `pip install -r requirements.txt`, проверить активацию venv |
| Не найдена версия 1С (venv) | платформа не установлена в одном из ожидаемых путей | см. список путей ниже |

Пути, которые сканирует `platforms.py` (Windows и Linux; macOS не поддерживается —
код содержит только эти две ветки):

**Windows:** `C:\Program Files\1cv8\`, `C:\Program Files (x86)\1cv8\`, `C:\Program Files\1C\1CE\1cv8\`
**Linux:** `/opt/1cv8/x86_64/`, `/opt/1C/v8.3/x86_64/`, `/opt/1C/v8.5/x86_64/`

В Docker эти же пути — точки монтирования: `/opt/1cv8/x86_64` принимает
bind-mount реальной установки (`docker-compose.override.yml.example`) или том
`syntaxmcp-hbk` с файлами, загруженными через веб-панель.

Искомые файлы в `<установка>/<версия>/bin/`: `shcntx_ru.hbk` (обязателен, справка
BSL), `shquery_ru.hbk` (язык запросов), `shlang_ru.hbk` (операторы BSL),
`shclang_ru.hbk`, `shcntx_root.hbk` (английское зеркало — оба обнаруживаются, но
в сборку индекса пока не участвуют). Если `shcntx_ru.hbk` не найден ни у одной
установленной версии — это тонкие клиенты без справки; нужна полная версия
платформы либо `.hbk` от другой машины.

## Разработка

### Структура проекта

```
1c-syntax-mcp/
├── server.py              # MCP-сервер: инструменты, транспорты (stdio/HTTP), CLI
├── config.py              # Настройки: env + CLI, единая точка (SYNTAX_MCP_*)
├── index_manager.py       # Реестр индексов: кеш SyntaxDB, безопасная пересборка, задачи панели
├── webapp.py               # HTTP-транспорт MCP + веб-панель (Starlette/uvicorn), Docker-режим
├── web/                    # Статика панели: panel.html/css/js (офлайн, без CDN)
├── platforms.py            # Обнаружение всех установленных версий платформы
├── hbk_reader.py           # Чтение .hbk (стандартная библиотека, без внешних утилит)
├── html_parser.py          # Структурный разбор страниц справки (lxml)
├── segmentation.py         # Сегментация PascalCase-идентификаторов + глоссарий
├── normalization.py        # Регистр/ё, гомоглифы, раскладка ЙЦУКЕН↔QWERTY
├── morphology.py           # Стемминг Snowball (ru/en) для полнотекстового поиска
├── aliases.py               # Курируемая таблица алиасов намерений
├── validate.py              # Честная проверка арности вызова
├── syntax_db.py             # Схема SQLite+FTS5, сборка, чтение индекса, diff версий
├── index/<версия>/syntax_index.sqlite  # Индекс синтаксиса (создаётся автоматически, по версии)
├── uploads/<версия>/bin/    # .hbk, загруженные через панель (только Docker/HTTP-режим)
├── Dockerfile, docker-compose.yml, .dockerignore  # Docker-развёртывание
├── docker-compose.override.yml.example  # Пример bind-mount установки 1С (сценарий А)
├── .env.example             # Шаблон переменных окружения для docker-compose
├── INSTALL-AGENT.md         # Инструкция для AI-агента: установить сервер самостоятельно
├── skills/1cskills/         # Навык для AI-ассистентов, работающих с кодом 1С
├── docs/IMPROVEMENT_PLAN.md # Аудит и план развития поиска
├── tests/                   # Golden-set и замер качества поиска
├── venv/                    # Виртуальное окружение Python (только для локальной установки)
└── README.md                 # Этот файл
```

### Тесты

```bash
python tests/test_search_quality.py
```

Прогоняет 42 контрольных запроса (`tests/golden_set.py`) против уже собранного
индекса (соберите его заранее — `python server.py --build-index`, либо укажите
готовый файл через `SYNTAX_MCP_DB=путь/к/syntax_index.sqlite`) и сравнивает
recall@5 и MRR с зафиксированной базовой линией (0.881 / 0.785). Тест
пропускается с понятным сообщением, если индекс не найден — не собирает его сам.

### Версия схемы индекса

`SCHEMA_VERSION = 4` (`syntax_db.py`). При изменении схемы старые индексы
автоматически пересобираются при следующем обращении (если исходный `.hbk`
всё ещё доступен) — вручную ничего чистить не нужно.

## Технические детали

- **Язык:** Python 3.12+
- **Библиотеки:** `mcp` (Model Context Protocol), `lxml` (разбор HTML), `rapidfuzz`
  (опечатки), `snowballstemmer` (морфология), `starlette`/`uvicorn`/`anyio`
  (HTTP-транспорт и веб-панель — используются только в Docker-режиме)
- **Внешние утилиты:** не требуются — `.hbk` читается через стандартную библиотеку
- **Транспорты:** stdio (локальная установка) и streamable HTTP + веб-панель
  (Docker, порт 8765 по умолчанию)
- **Docker:** образ на `python:3.12-slim`, ~270 МБ; данные (`.hbk` и собранные
  индексы) только в томах — в образ не попадают
- **Поддержка версий 1С:** 8.3.x, 8.5.x, несколько версий одновременно
- **Поддержка языков:** русский и английский; встроенный язык (BSL) и язык
  запросов (SDBL)
- **Источник данных:** `shcntx_ru.hbk`, `shquery_ru.hbk`, `shlang_ru.hbk` из
  установленной платформы 1С
- **Поддержка ОС хоста:** Windows, Linux
