# 1C Syntax MCP Server

MCP-сервер для проверки синтаксиса 1С:Предприятие с автоматической инициализацией.

Публикация на Инфостарт:
https://infostart.ru/1c/articles/2657968/

![Инфостарт](https://infostart.ru/bitrix/templates/sandbox_empty/assets/tpl/abo/img/logo.svg)

## Описание

Этот MCP-сервер предоставляет инструменты для работы с синтаксисом 1С:
- Полнотекстовый поиск функций, методов, свойств и объектов (русский/английский,
  ранжирование по релевантности — bm25 + сегментация идентификаторов + алиасы),
  устойчивый к опечаткам и раскладке клавиатуры (fuzzy + ЙЦУКЕН↔QWERTY)
- Получение детальной информации о функциях, включая структурные параметры
  (имя, тип, обязательность, описание)
- Точная адресация `Объект.Метод` без коллизий одноимённых членов у разных объектов
- Автодополнение по частичному имени
- Проверка вызова функции: существование имени и, где выводимо из кода, арность
- Встроенный язык (BSL) и язык запросов (SDBL) — раздельно через параметр `language`
- Работа с несколькими установленными версиями платформы одновременно, включая
  сравнение (`diff`) между версиями

Обоснование архитектуры и план дальнейшего развития — [docs/IMPROVEMENT_PLAN.md](docs/IMPROVEMENT_PLAN.md).

## Навык 1С (1cskills)

В репозитории включён навык **1cskills** — набор правил и рекомендаций для AI-ассистентов при работе с кодом на языке 1С. Навык описывает:

- Обязательный алгоритм проверки синтаксиса через MCP
- Контекст выполнения и директивы (`&НаКлиенте`, `&НаСервере` и т.д.)
- Структуру областей (Regions) для модулей объектов, менеджеров, форм и общих модулей
- Структуру файлов проекта (XML-дамп конфигурации)
- Библиотеку стандартных подсистем (БСП) и типовые паттерны
- Именование переменных, документирование кода, пометки изменений
- Язык запросов 1С (ВЫБРАТЬ, соединения, агрегатные функции, временные таблицы и др.)
- Регулярные выражения в 1С

### Установка навыка

Скопируйте навык в директорию навыков вашего AI-ассистента:

**OpenCode:**
```bash
# Windows
mkdir "%APPDATA%\opencode\skills\1cskills"
copy skills\1cskills\SKILL.md "%APPDATA%\opencode\skills\1cskills\SKILL.md"

# Linux/Mac
mkdir -p ~/.config/opencode/skills/1cskills
cp skills/1cskills/SKILL.md ~/.config/opencode/skills/1cskills/SKILL.md
```

Навык автоматически активируется при работе с файлами `.bsl` и `.os`.

## Особенности

При первом запуске сервер **автоматически**:
1. Находит установленную версию 1С со справкой (8.3.x или 8.5.x); если новейшая
   версия — тонкий клиент без справки, ищет более старую версию, у которой она есть
2. Читает `shcntx_ru.hbk`/`shquery_ru.hbk`/`shlang_ru.hbk` напрямую через
   стандартную библиотеку Python (`.hbk` — контейнер 1Cv8, не 7z-архив; внешние
   утилиты не требуются)
3. Разбирает HTML структурно (через `lxml`) и строит SQLite-индекс с
   полнотекстовым поиском (FTS5, ~40 МБ на версию платформы)

На реальных данных сборка занимает около 10 секунд. Собрать индекс явно, не запуская
сервер:

```bash
python server.py --build-index                        # новейшая версия со справкой
python server.py --build-index --platform=8.3.19.1264  # конкретная версия
python server.py --build-index --all                   # все версии со справкой
python server.py --build-index --force                 # пересобрать, даже если актуален
```

Индекс каждой версии хранится отдельным файлом `index/<версия>/syntax_index.sqlite`
и сверяется по SHA-256 файла `.hbk` — если он не менялся, сервер запускается с уже
собранным индексом мгновенно, без пересборки. Все инструменты принимают
необязательный параметр `platform`; по умолчанию используется новейшая версия
с уже собранным индексом.

## Установка

### 1. Создать виртуальное окружение

```bash
cd 1c-syntax-mcp
python -m venv venv
venv\Scripts\activate  # Windows
# или
source venv/bin/activate  # Linux/Mac
```

### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

Внешние утилиты (7z и т.п.) не требуются — `.hbk` читается через стандартную
библиотеку Python.

### 3. Настроить OpenCode

Добавьте в `%APPDATA%\opencode\opencode.jsonc` (Windows) или `~/.config/opencode/opencode.jsonc` (Linux/Mac):

**Windows:**
```json
{
  "mcp": {
    "1c-syntax": {
      "type": "local",
      "command": ["C:\\Users\\<username>\\1c-syntax-mcp\\venv\\Scripts\\python.exe", "C:\\Users\\<username>\\1c-syntax-mcp\\server.py"],
      "enabled": true
    }
  }
}
```

**Linux/Mac:**
```json
{
  "mcp": {
    "1c-syntax": {
      "type": "local",
      "command": ["~/1c-syntax-mcp/venv/bin/python", "~/1c-syntax-mcp/server.py"],
      "enabled": true
    }
  }
}
```

### 4. Проверить подключение

```bash
opencode mcp list
```

Вы должны увидеть `1c-syntax` в списке подключенных серверов.

При первом запуске сервер автоматически найдёт и проиндексирует документацию из установленной 1С (занимает около 10 секунд).

## Использование

### Поиск функций

```
use 1c-syntax to search for СтрДлина
```

### Получить информацию о функции

```
use 1c-syntax to get info about СтрДлина
```

### Автодополнение

```
use 1c-syntax to suggest completions for Стр
```

### Валидация синтаксиса

```
use 1c-syntax to validate: СтрДлина("текст")
```

## Доступные инструменты

### search_syntax
Полнотекстовый поиск функций, методов, свойств и объектов 1С — по имени, фразе на
естественном языке или описанию.

**Параметры:**
- `query` (string, обязательный) - запрос
- `limit` (number, опциональный) - максимум результатов (по умолчанию 10)
- `kind` (string, опциональный) - сузить по типу: `object`/`method`/`property`/`event`/`ctor`
- `owner` (string, опциональный) - сузить до конкретного объекта-владельца

**Пример:**
```json
{
  "query": "как обрезать пробелы в строке",
  "limit": 5
}
```

### get_function_info
Получить детальную информацию о функции, методе или свойстве, включая структурные
параметры (имя, тип, обязательность, описание). Если имя неоднозначно (несколько
объектов-владельцев имеют член с таким именем), возвращает список кандидатов вместо
случайного выбора — уточните `owner` или используйте `get_by_fqn`.

**Параметры:**
- `name` (string, обязательный) - точное имя
- `owner` (string, опциональный) - объект-владелец, если имя неоднозначно

**Пример:**
```json
{
  "name": "СокрЛП"
}
```

### get_by_fqn
Получить детальную информацию по полному имени вида `Объект.Метод` — однозначная
адресация без коллизий имён.

**Параметры:**
- `fqn` (string, обязательный) - например: `ЗаписьJSON.ЗаписатьНачалоОбъекта`

**Пример:**
```json
{
  "fqn": "Глобальный контекст.ЗаписатьJSON"
}
```
![1C Syntax MCP](pics/pic.png)

### suggest_completion
Предложить автодополнение по частичному имени.

**Параметры:**
- `prefix` (string, обязательный) - начало имени функции
- `limit` (number, опциональный) - максимум предложений (по умолчанию 10)

**Пример:**
```json
{
  "prefix": "Стр",
  "limit": 10
}
```

### validate_syntax
Проверить вызов функции: существование имени и, где это выводимо из переданного
кода, арность вызова (по структурным параметрам справки). Поддерживает разрешение
вызовов через точку (`Получатель.Метод`), если тип получателя присвоен в этом же
коде через `Х = Новый Тип(...)`. **Честно не проверяет** реальный вывод типов, поток
управления и объекты метаданных конфигурации — в этих случаях возвращает
неопределённый результат вместо угадывания.

**Параметры:**
- `code` (string, обязательный) - код для проверки
- `language` (string, опциональный) - `bsl` (по умолчанию) или `sdbl`
- `platform` (string, опциональный) - версия платформы

**Примеры:**
```json
{"code": "СтрДлина(\"текст\")"}
{"code": "Х = Новый Массив; Х.Добавить(1)"}
```

### list_versions
Список установленных версий платформы: у каких есть справка, какие уже
проиндексированы, сколько элементов в индексе каждой.

### diff_versions
Сравнить две версии платформы: что добавлено/удалено/изменено в справке между
ними. Обе версии должны быть предварительно собраны
(`python server.py --build-index --platform=<версия>`).

**Параметры:**
- `from_version`, `to_version` (string, обязательные) - например `8.3.19.1264`, `8.5.1.1150`

## Структура проекта

```
1c-syntax-mcp/
├── server.py              # MCP-сервер: инструменты, обнаружение платформы, автоинициализация
├── platforms.py           # Обнаружение всех установленных версий платформы
├── hbk_reader.py          # Чтение .hbk (стандартная библиотека, без внешних утилит)
├── html_parser.py         # Структурный разбор страниц справки (lxml)
├── segmentation.py        # Сегментация PascalCase-идентификаторов + глоссарий
├── normalization.py       # Регистр/ё, гомоглифы, раскладка ЙЦУКЕН↔QWERTY
├── aliases.py             # Курируемая таблица алиасов намерений
├── validate.py            # Честная проверка арности вызова
├── syntax_db.py           # Схема SQLite+FTS5, сборка, чтение индекса, diff версий
├── index/<версия>/syntax_index.sqlite  # Индекс синтаксиса (создаётся автоматически, по версии)
├── docs/IMPROVEMENT_PLAN.md  # Аудит и план развития поиска
├── tests/                 # Golden-set и замер качества поиска
├── venv/                  # Виртуальное окружение Python
└── README.md              # Этот файл
```

## Технические детали

- **Язык:** Python 3
- **Библиотеки:** `mcp` (Model Context Protocol), `lxml` (разбор HTML при сборке индекса), `rapidfuzz` (опечатки)
- **Внешние зависимости:** нет — `.hbk` читается через стандартную библиотеку
- **Поддержка версий 1С:** 8.3.x, 8.5.x, несколько версий одновременно
- **Поддержка языков:** русский и английский; встроенный язык (BSL) и язык запросов (SDBL)
- **Источник данных:** shcntx_ru.hbk, shquery_ru.hbk, shlang_ru.hbk из установленной платформы 1С
- **Поддержка платформ:** Windows, Linux, macOS

## Troubleshooting

### Сервер не запускается

Проверьте, что:
1. Виртуальное окружение активировано
2. Зависимости установлены: `pip install -r requirements.txt`
3. Файл `index/<версия>/syntax_index.sqlite` существует — если нет, соберите
   явно: `python server.py --build-index`

### Не найдена версия 1С

Сервер ищет установки в:

**Linux:**
- `/opt/1cv8/x86_64/`
- `/opt/1C/v8.3/x86_64/`
- `/opt/1C/v8.5/x86_64/`

**Windows:**
- `C:\Program Files\1cv8\`
- `C:\Program Files (x86)\1cv8\`
- `C:\Program Files\1C\1CE\1cv8\`

Убедитесь, что платформа 1С установлена в одном из этих каталогов.

### Файл shcntx_ru.hbk не найден

**Linux:**
```bash
find /opt -name "shcntx_ru.hbk" 2>/dev/null
```

**Windows:**
```cmd
dir "C:\Program Files\1cv8" /s /b | findstr shcntx_ru.hbk
```

Если файл отсутствует ни у одной установленной версии — это тонкие клиенты без
справки; установите полную версию платформы, либо укажите версию с `.hbk` вручную.
