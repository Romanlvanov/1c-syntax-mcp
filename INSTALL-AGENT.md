# Установка 1C Syntax MCP — инструкция для AI-агента

Это не текст для человека — это промпт. Скопируйте содержимое этого файла целиком
в чат Claude (Claude Code или любой другой агент с доступом к терминалу и Docker)
на машине, где нужен сервер. Агент выполнит установку сам, следуя шагам ниже.

Покрывает только Docker-развёртывание. Если Docker недопустим (политика
безопасности, нет прав на установку) — остановитесь на первом шаге и разверните
локально через venv по README.md, раздел «Установка → Вариант 2».

---

## Инструкции для агента

Ты разворачиваешь MCP-сервер 1C Syntax MCP — он отдаёт LLM полнотекстовый поиск
по официальной справке 1С:Предприятие (BSL и язык запросов SDBL) через Docker-
контейнер с HTTP-транспортом. Выполняй шаги по порядку. На каждом шаге проверяй
результат командой из этого же шага, прежде чем переходить к следующему. Если
шаг дал не то, что ожидается — не выдумывай обходной путь, покажи пользователю
фактический вывод команды и спроси, как быть.

### Шаг 0. Проверить предусловия

```bash
docker --version
docker compose version
git --version
```

Если любая из команд не найдена — остановись и сообщи пользователю: Docker
Desktop (или Docker Engine + Compose plugin) должен быть установлен и запущен
до продолжения. Не пытайся ставить Docker сам.

**Про порт 8765**: все команды ниже (шаги 2-5) написаны с портом `8765` — это
дефолт `docker-compose.yml`. Если он уже занят на этой машине, `docker compose up`
в шаге 3 сообщит `port is already allocated`; тогда один раз выбери свободный
порт, запускай контейнер как `HOST_PORT=<порт> docker compose up -d` и дальше
подставляй именно его вместо `8765` во ВСЕХ командах шагов 2-5, не только в
команде запуска — иначе `curl`/`claude mcp add` будут стучаться в порт, на
котором никто не слушает.

### Шаг 1. Клонировать репозиторий

```bash
git clone https://github.com/Romanlvanov/1c-syntax-mcp.git
cd 1c-syntax-mcp
```

Если каталог `1c-syntax-mcp` уже существует и это git-репозиторий с тем же
origin — используй его (`git pull`), не клонируй повторно.

### Шаг 2. Определить источник данных — три варианта, в этом порядке

Сервер собирает поисковый индекс из файла `shcntx_ru.hbk`, входящего в состав
любой полной установки платформы 1С:Предприятие (не тонкий клиент). Файл не
универсален — переносить его дозволено только для собственного использования,
не публиковать и не распространять.

**Проверь по порядку и выбери первый подходящий вариант:**

**Вариант А — 1С установлена на этой же машине.**

Проверяй не сам факт существования каталога, а наличие внутри него хотя бы
одного `shcntx_ru.hbk` — каталог `1cv8` может существовать и быть пустым.

Windows (проверь оба пути, они независимы — на одной машине бывают оба сразу):
```powershell
Get-ChildItem "C:\Program Files\1cv8" -Recurse -Filter shcntx_ru.hbk -ErrorAction SilentlyContinue
Get-ChildItem "C:\Program Files (x86)\1cv8" -Recurse -Filter shcntx_ru.hbk -ErrorAction SilentlyContinue
```
Linux:
```bash
find /opt/1cv8/x86_64 /opt/1C -name shcntx_ru.hbk 2>/dev/null
```

Если хотя бы одна команда вернула путь — это вариант А. Действие:
```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```
Открой `docker-compose.override.yml` и поправь путь `volumes:` под фактически
найденную установку (на Windows путь пишется с прямыми слэшами и в кавычках,
например `"C:/Program Files/1cv8:/opt/1cv8/x86_64:ro"`). **Если файлы нашлись
сразу в обоих путях** (`Program Files` и `Program Files (x86)`) — не выбирай
один, добавь в `volumes:` обе строки, каждую со своим путём на хосте и **одной
и той же** точкой монтирования `/opt/1cv8/x86_64` не получится (Docker не даёт
смонтировать два источника в одну точку) — вместо этого используй под второй
путь `/opt/1cv8/x86_64_alt:ro` и допиши в `SYNTAX_MCP_PLATFORM_PATHS=/opt/1cv8/x86_64_alt`
(переменная окружения сервиса в том же файле). Если не уверен — смонтируй
только тот путь, где `Get-ChildItem`/`find` нашёл больше версий.

Дальше переходи к шагу 3 — загружать файлы вручную не нужно, версии
обнаружатся автоматически.

**Вариант Б — `.hbk`-файлов на диске нет, но они у тебя есть (например, скопированы
с другого компьютера, путь дал пользователь).**

Тебе нужен как минимум `shcntx_ru.hbk` (обязателен), опционально `shquery_ru.hbk`
и `shlang_ru.hbk`. Не создавай `docker-compose.override.yml`. Выполни шаг 3
(поднять контейнер), затем загрузи файлы через API — это ты делаешь сам, без
участия пользователя:

```bash
# версия — имя каталога установки, из которого взяты файлы, например 8.5.1.1150
VERSION=8.5.1.1150

curl -X PUT --data-binary @shcntx_ru.hbk \
  "http://127.0.0.1:8765/api/uploads/${VERSION}/shcntx_ru"
# ожидаемый ответ: {"version":"...","kind":"shcntx_ru","size":...,"sha256":"...","member_count":52807}

# опционально, если файлы есть:
curl -X PUT --data-binary @shquery_ru.hbk "http://127.0.0.1:8765/api/uploads/${VERSION}/shquery_ru"
curl -X PUT --data-binary @shlang_ru.hbk  "http://127.0.0.1:8765/api/uploads/${VERSION}/shlang_ru"

curl -X POST -H "Content-Type: application/json" -d '{}' \
  "http://127.0.0.1:8765/api/versions/${VERSION}/build"
# ответ: {"job_id":"...","version":"..."}
```

Дождись завершения сборки (~10-20 секунд на реальных данных):
```bash
JOB_ID=<job_id из ответа выше>
curl -s "http://127.0.0.1:8765/api/jobs/${JOB_ID}"
```
Повторяй, пока `"status"` не станет `"done"` (не `"running"`). `"status":"error"`
означает, что файл не подошёл — покажи пользователю поле `"error"` из ответа.

Если сервер вернул `{"error": "неверный или отсутствующий заголовок X-Panel-Token"}`
— значит на сервере задан `SYNTAX_MCP_PANEL_TOKEN`; спроси токен у пользователя
и добавляй его во все запросы выше через `-H "X-Panel-Token: <токен>"`.

**Вариант В — файлов нет вообще, и 1С на этой машине не установлена.**

Автоматизировать нечего — файл `shcntx_ru.hbk` физически должен откуда-то
появиться. Выполни шаг 3 (сервер поднимется и будет работать, просто без
данных), затем сообщи пользователю:

> Сервер поднят на `http://127.0.0.1:8765/`. Индекса пока нет. Откройте эту
> ссылку в браузере и загрузите файл `shcntx_ru.hbk` — он лежит в установке 1С
> на любой другой машине, где есть полная версия платформы, по пути
> `<каталог установки>\<версия>\bin\shcntx_ru.hbk` (Windows) или
> `<каталог установки>/<версия>/bin/shcntx_ru.hbk` (Linux). Панель сама
> запустит сборку после загрузки.

На этом твоя часть работы для варианта В закончена — дальнейшее делает
пользователь руками через веб-панель.

### Шаг 3. Поднять контейнер

```bash
docker compose up -d
```

Проверь, что контейнер стартовал и прошёл health-check (может занять до
90 секунд — столько отведено на автосборку индекса при варианте А):

```bash
docker compose ps
docker inspect --format '{{.State.Health.Status}}' 1c-syntax-mcp
```

Ожидаемое значение — `healthy`. Если долго `starting` — смотри логи:
```bash
docker compose logs -f syntax-mcp
```

Проверь напрямую:
```bash
curl -s http://127.0.0.1:8765/api/health
```
Ожидаемый ответ при варианте А: `{"ok":true,"ready":true,"default_version":"<версия>","fts5":true}`.
При варианте Б — `"ready":true` появится только после завершения сборки из шага 2.
При варианте В — `"ready":false,"default_version":null` до тех пор, пока пользователь не загрузит файл.

### Шаг 4. Подключить клиента

Если агент, который выполняет эту установку — сам Claude Code:
```bash
claude mcp add --transport http --scope user 1c-syntax http://127.0.0.1:8765/mcp
claude mcp list
```
В списке должен появиться `1c-syntax`. `--scope user` — сервер доступен во всех
проектах; для привязки к одному проекту используй `--scope project`.

Для opencode добавь в `%APPDATA%\opencode\opencode.jsonc` (Windows) или
`~/.config/opencode/opencode.jsonc` (Linux/Mac):
```jsonc
{
  "mcp": {
    "1c-syntax": {
      "type": "remote",
      "url": "http://127.0.0.1:8765/mcp",
      "enabled": true
    }
  }
}
```

Используй `127.0.0.1`, не `localhost` (на Windows может резолвиться и в `::1`).

### Шаг 5. Критерии успеха — проверь все три

1. `curl -s http://127.0.0.1:8765/api/health` → `"ready": true` и `"fts5": true`.
2. `claude mcp list` (или эквивалент для другого клиента) показывает `1c-syntax`
   подключённым.
3. Пробный вызов инструмента находит реальную функцию (запрос латиницей — не
   случайность: `curl -d` с кириллицей в аргументе искажается кодировкой консоли
   на некоторых системах, а поиск двуязычный и находит то же самое по `StrLen`):
   ```bash
   curl -s -X POST -H "Content-Type: application/json" \
     -d '{"query":"StrLen","limit":1}' \
     http://127.0.0.1:8765/api/search
   ```
   В ответе должно быть `"name_ru":"СтрДлина"`, `"name_en":"StrLen"`, `"tier":"exact"`.

Если все три пункта выполнены — установка завершена, сообщи пользователю адрес
панели (`http://127.0.0.1:8765/`) и что сервер подключён к клиенту.

## Диагностика (если что-то пошло не так)

| Симптом | Причина | Что делать |
|---|---|---|
| `docker compose up` падает: `port is already allocated` | порт 8765 занят другим процессом | `HOST_PORT=8766 docker compose up -d`, либо найти и остановить процесс на 8765 |
| `unhealthy` дольше ~90 секунд | автосборка индекса зависла или упала | `docker compose logs syntax-mcp`, искать `Ошибка сборки` |
| `PermissionError` при первой сборке индекса | том создан не тем пользователем (редко, но бывает после `docker volume create` вручную) | `docker compose down -v && docker compose up -d` — свежий том унаследует владельца из образа |
| Bind-mount не находит версии (вариант А) | путь в `docker-compose.override.yml` не совпадает с фактической установкой, или в пути пробел без кавычек | проверь `docker exec 1c-syntax-mcp ls /opt/1cv8/x86_64/` — должны быть видны каталоги версий |
| `curl: (7) Failed to connect` | контейнер ещё не поднялся или порт не тот | `docker compose ps`, дождись `Up` |
| Клиент подключился, но инструменты не находят индекс | ни один из вариантов А/Б/В не довёл дело до собранного индекса | `curl http://127.0.0.1:8765/api/state`, посмотри поле `versions` |

## Чего не делать

- Не коммитить и не публиковать `.hbk`-файлы или собранные из них
  `*.sqlite`-индексы — это проприетарная документация 1С.
- Не открывать порт 8765 наружу (`0.0.0.0` вместо `127.0.0.1` в `docker-compose.yml`)
  без отдельного запроса пользователя — панель и MCP по умолчанию без аутентификации.
- Не запускать `docker compose down -v`, если в варианте Б уже загружены `.hbk` —
  это удалит их без возможности восстановления, если исходники больше недоступны.
